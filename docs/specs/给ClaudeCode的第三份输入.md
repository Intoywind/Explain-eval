## 1. 计分程序：没有有效证据不能清零（最优先）

现状（`src/scoring.py` 的 `score`）：`knowledge_pass = not p.knowledge_found`。裁判只要返回 `found=true`，哪怕 `which` 和 `quotes` 都是空的，卡点分和步骤分也会清零。GPT 在本地复现过：IEDA-003 那份原本卡点 1/1、步骤 5/5，只把裁判结果改成 `found=true`、清单项和引句留空，两项就变成 0。

改成：

- 触发知识清零必须同时满足三条：
  1. `found` 为 true；
  2. `which` 不为空，且每一条都能对上这条条目 `knowledge_errors` 里的某一项（去掉首尾空白后相同；对不上的算无效）；
  3. `quotes` 里至少有一条通过引句校验。
- 三条不全满足时，不清零，也不当成“知识通过”：把它当成格式错误，让裁判重判同一份回答，最多 2 次。
- 卡点问题 `answered` 为 true、推荐步骤 `done` 为 true 但没有任何一条引句通过校验时，同样处理：不再改判成没答上，重判，最多 2 次。
- 重判后仍不合格的，这份回答的裁判结果整份标成 `needs_review`（待复核）：存下原始输出和不合格的原因，不算三档分，不进任何统计，报告里单独列出份数和清单，由我人工看。
- 补单元测试，至少包括：`found=true` 且 `which`、`quotes` 为空，不清零、进重判；`found=true` 且 `which` 对不上清单，同上；`found=true`、`which` 对得上、引句有效，清零；某个卡点 `answered=true` 引句全部无效，进重判而不是改判。

理由：引句核对不上是裁判抄错了原文，旧做法把这个错算到被测回答头上。

## 2. 裁判 prompt 换成 `prompts/judge_v2.md`

`judge_v1.md` 保留不动。命令改成 `python -m src.judge --prompt prompts/judge_v2.md`。相对 v1 的改动写在 v2 文件头的注释里，要点：

- 知识错误：只有讲解自己最终主张的内容就是清单描述的那种错误才触发；先提误区再否定的不触发；清单外的事实错误写进 `note`（以“清单外：”开头），不触发，也不记成 gaps。
- 推荐步骤：位置仍然不限；步骤文字写明依据关系的，要看讲解有没有把前一件事当作后一件事的理由讲出来；括号里的“应为”“例如”只作参考。
- 引句必须是真正做到这件事的那段话，只预告不算；标清含义的算式、表格、真值表、时间线可以当证据。
- gaps 的 `severity` 按“读者能不能完成请求”判；请求没要求的补充内容里的缺口只标“只是不顺”。

> 为什么最后会停在两边相等的那个利率上？因为两边不相等时，利率自己会动。如果利率偏高，人们想持有的货币比中央银行提供的少，手里多出来的钱就会被拿去换成能生利息的资产，愿意把钱借出去的人变多，利率被压低；利率一降，人们又愿意多持有一些货币。如果利率偏低，情况相反：人们想持有的货币比现有的多，就会把生息的资产换回钱，利率被抬高。利率就这样一直变，直到人们想持有的数量正好等于中央银行提供的数量才停下来。停下来时的利率就叫均衡利率，题目问的就是它。
