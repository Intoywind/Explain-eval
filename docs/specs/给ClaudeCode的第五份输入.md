# 给 Claude Code 的第五份输入：不带 Skill 的基线

2026-11-11。可以和第四份并行做，互不依赖。

## 为什么做

四组结果里，通用 V1 和原课程 Skill 的“卡点全部答上”占比在两个模型上都一样（91.1%、72.2%）。要回答“Skill 对卡点到底有没有作用”，缺一组对照：完全不给 Skill，只给读者设定、材料和请求。

- 不带 Skill 也在 91% 和 72% 附近：现有短题的卡点测的主要是模型自己的水平，Skill 没起可测的作用。
- 不带 Skill 明显更低：两份 Skill 都起了作用，而且作用差不多大。

## 怎么做

1. 新增一组“不带 Skill”：不发 system 消息（接口必须有 system 时发空字符串，并在报告里写明用的是哪一种）。user 消息的拼法和其他组完全一样（读者设定、材料、请求）。组名用 `no_skill`。
2. 条目用 `data/items.jsonl` 的 30 条，每条重复 3 次，两个模型各跑一遍（gpt-6.1-sol、gpt-6-luna），共 180 次调用。模型参数和其他组相同。
3. 用 `prompts/judge_v2.md` 判这 180 份，规则不变。
4. 四组汇总扩成六组，2×2 表扩成 3×2（不带 Skill / 通用 V1 / 原课程 Skill × sol / luna），每格给知识通过率、卡点分、步骤分、卡点全部答上占比。再给逐条目的对比：不带 Skill 相对通用 V1，卡点分升、平、降各多少条。
5. 报告平均回答字数、花费。预估生成约 1.7 美元、判分约 2 美元；超过 6 美元先停下来告诉我。
6. 这组数据不进盲标包，`blind/round1/` 不要重新导出。
