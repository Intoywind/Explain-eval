## 为什么做

通用 V2（`skills/general_v2.md`，现在是第五稿）是照 V1 在 30 条短题上的失败全面改写的。它一次都没跑过。正式测试（V1 对 V2，短题加长题一共 60 条）开跑以后，Skill 就不能再改了，所以开跑前要先确认 V2 没有写坏。

这一步在已经跑过 V1 的 30 条短题上跑 V2，看四件事：

1. V1 没答上的卡点，换成 V2 以后有没有补上。
2. V2 有没有带来新的问题：知识讲错变多、原来答上的卡点反而丢了。
3. V2 的回答比 V1 长多少，对学过前置内容的读者是不是讲得太啰嗦。
4. 请求只问一处的时候，V2 是不是只讲这一处，没有把整份材料重讲一遍。

这是开发题上的检查。V2 就是看着这批题的失败写的，所以补得回来只说明 V2 没写偏，不能当作 V2 有效的证据。而且强模型在短题上本来就有 95% 的卡点答上了，这里看不出多大差别是正常的。V2 到底有没有用，要等正式测试里的长题。

1. **汇总**：每个模型下 V1、V2 各自的知识通过率、卡点分、步骤分、“卡点全部答上”的份数占比（算法和四组汇总一致）；另外给不套知识清零的卡点答上率（直接用每个卡点的 `answered`），V1 对 V2 差多少个百分点；51 个卡点里上升、持平、下降各几个。按课程、按读者版本（零基础 / 有前置）各算一遍。
2. **逐卡点对比表**（51 行 × 2 个模型）：V1 答上几次、V2 答上几次（各 3 次）。
3. **重点看的卡点**：V1 没有每次都答上的卡点（按模型分别从已有裁判记录里筛；我从数据库数的是 sol 7 个、luna 12 个，例如 `COMP-001` 的 q1、`ECON-001` 的 q1、`ECON-003` 的 q1，数不一样请告诉我）。每个卡点列 V1、V2 的答上次数；V2 答上的，摘一句裁判引的原句；V2 还是没答上的，贴裁判的判语。
4. **V2 变差的卡点**：V1 答上而 V2 没答上的，逐个列出裁判的判语。
5. **推荐步骤**：103 个步骤 V1 对 V2 的汇总，逐条表放附录。V1 的 6 份回答（两个模型各 3 次）里一次都没做到的步骤单独列出来，看 V2 做到了几次。
6. **篇幅和冗余**：每份回答的字数，V2 ÷ V1 的比例（按条目和重复序号配对），按模型、按读者版本汇总；比例超过 2 的条目单独列出来。裁判记下的冗余条数（只统计有前置版）V1 对 V2。V2 的规则接近 V1 的四倍长，要看它是不是只靠写得更长。V2 里有一张“好坏对照”表，例子是编程入门的；请统计 V2 的回答里有没有出现 double、二分查找这类和题目无关的内容（出现就列出来）。
7. **知识错误和没答全**：V2 的份数和所在条目，对比 V1。V2 新出现的知识错误逐条贴裁判的判语。
